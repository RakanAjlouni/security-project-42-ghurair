Origin Validation Error

CWE-346 · OWASP A08:2021 Software and Data Integrity Failures (verify mapping)

What it is

An Origin Validation Error (CWE-346) happens when an app trusts data without checking which website sent it. With postMessage(), any open page can message your page, so an untrusted site can trigger trusted actions.

The vulnerable code

window.addEventListener('message', (event) => {
  const message = event.data;   // never checks event.origin
  balance -= message.amount;
  render();
});

The handler uses event.data without checking event.origin, so any website can make the app move money.

    Why it matters

    A page that trusts any sender can be told to move money, change settings or leak data by any site the visitor has open. I am not citing a specific incident here; MDN's postMessage security notes and CWE-346 describe the pattern.

    The fix

    Switch modes below and re-run your last payload to see the difference.

    const ALLOWED_ORIGINS = ['https://app.ghurir.example'];
window.addEventListener('message', (event) => {
  if (!ALLOWED_ORIGINS.includes(event.origin)) return;
  const m = event.data;
  const valid = m && m.type === 'transfer' && Number.isFinite(m.amount) && m.amount > 0 && m.amount <= balance;
  if (!valid) return;
  balance -= m.amount;
});

    The receiver compares event.origin to an exact allowlist, then checks the message shape. Limitation: scripts cannot forge a real event.origin, so senders are simulated by dispatching a real MessageEvent with the origin each sender would have; the same listener and validation logic run in the demo.
