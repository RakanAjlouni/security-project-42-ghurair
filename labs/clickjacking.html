Clickjacking

CWE-1021 · OWASP A04:2021 Insecure Design

Clickjacking lets an attacker load your page invisibly under a decoy button, so the visitor's click triggers an action they never meant to perform. It works because the browser only refuses to show a page inside another site if the server tells it to, with a header.

Real-world impact

Why it matters

If an attacker hides a sensitive button—such as deleting an account, changing privacy settings, or approving a transfer—under a fake offer, a single click can cause real damage without the user noticing. Clickjacking bugs have historically affected major web platforms and social apps when framing headers were missing on sensitive actions.

Code analysis

The vulnerable code

VULNERABLE CODE · Express / JavaScript 
                const express = require('express');
                const app = express();

                app.get('/settings', requireLogin, (req, res) => {
                  // No X-Frame-Options and no CSP frame-ancestors header
                  res.send(settingsPageHtml);
                });

                app.post('/settings/delete-account', requireLogin, (req, res) => {
                  deleteAccount(req.user);
                  res.send('Account deleted');
                });

                app.listen(3000);

The page is returned without a framing policy. Another site can therefore load it inside an invisible iframe and place it over a misleading button.

Remediation

The fixed code

SECURE CODE · Express / JavaScript 
                const express = require('express');
                const app = express();

                app.get('/settings', requireLogin, (req, res) => {
                  res.set('Content-Security-Policy', "frame-ancestors 'self'");
                  res.set('X-Frame-Options', 'SAMEORIGIN');
                  res.send(settingsPageHtml);
                });

                app.post('/settings/delete-account', requireLogin, (req, res) => {
                  deleteAccount(req.user);
                  res.send('Account deleted');
                });

                app.listen(3000);

These headers restrict which sites are allowed to embed the page. The simulation demonstrates this browser decision; a real application must send the headers from its server.
