Clickjacking

CWE-1021 · OWASP A04:2021 Insecure Design (verify mapping)

What it is

Clickjacking (CWE-1021, Improper Restriction of Rendered UI Layers or Frames) lets an attacker embed your page invisibly under a decoy so the visitor's click triggers an action they never intended. The browser only refuses to frame the page if the server says so with a header.

The vulnerable code

app.get('/settings', (req, res) => {
  // no X-Frame-Options, no CSP frame-ancestors
  res.send(settingsPageHtml);
});

The response carries no framing policy, so any site, such as evil.example, may load this page in an invisible iframe.

Why it matters

A hidden click can change settings, approve payments or delete accounts using the victim's logged-in session. A clickjacking worm spread on Twitter in 2009 (see Wikipedia's Clickjacking article).

The fix

Switch modes below and re-run your last payload to see the difference. 

app.get('/settings', (req, res) => {
  res.set('Content-Security-Policy', "frame-ancestors 'self'");
  res.set('X-Frame-Options', 'SAMEORIGIN'); // older browsers
  res.send(settingsPageHtml);
});

The browser reads these headers and refuses to render the page inside other origins. Limitation: with no backend, this demo only simulates that browser decision by parsing the same header value; JavaScript alone cannot provide this protection, so real sites must set the headers on the server.
